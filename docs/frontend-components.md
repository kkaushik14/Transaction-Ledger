# Frontend component contracts

The approved v0.2 implementation follows this order: tokens and component contracts, UI primitives, shell/navigation, landing sections and domain features, then page composition. All components use the monochrome tokens and semantic HTML. No transfer controls are included.

| Component                                       | Typed public inputs                                                                       | States and semantics                                                                                                               |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Button / ButtonLink                             | Native button or router-link props; primary/secondary/subtle variant; loading for buttons | Native disabled state; loading label and aria-busy; links keep navigation semantics                                                |
| IconButton                                      | Required accessible label, icon, native button props                                      | 44px touch target and visible focus                                                                                                |
| TextField / TextAreaField / SelectField         | Label, optional hint/error, native control props                                          | Stable label/control IDs; error descriptions and aria-invalid; native keyboard behavior                                            |
| Card / Container / SectionHeading               | Children, class names, layout/heading variant                                             | Consistent spacing and borders; logical semantic headings                                                                          |
| StatusMessage / LoadingState                    | Message/title, info/success/error tone                                                    | Text/icon feedback; alert for errors and polite status for progress/success                                                        |
| Pagination                                      | Server page, total pages/records, loading, onPageChange                                   | Descriptive previous/next controls, disabled boundaries, empty result state                                                        |
| AppShell / SiteHeader / DesktopNav / SiteFooter | Router context and children/outlet                                                        | Shared landmarks, real links, skip link, active route, anchor focus/scroll                                                         |
| ResponsiveSidebar                               | Open/close callback and trigger reference                                                 | Native modal dialog: focus containment, Escape/backdrop/link close, focus restore, scroll lock, desktop reset                      |
| Landing sections                                | Composed primitives and real account-entry controls                                       | Hero, features, steps, principles, account entry, final CTA; no fake metrics or unsupported claims                                 |
| AccountCreateForm / AccountLookupForm           | Feature orchestration through hooks/API adapters                                          | Shared validation, pending/error states, safe navigation; no database credentials                                                  |
| AccountBalanceCard / AccountPageHeader          | API balance, UUID, optional known name, refresh state                                     | Exact decimal display; Account/UUID fallback; clipboard feedback                                                                   |
| TransactionForm                                 | Account ID and authoritative refresh callback                                             | New reference per intent; freeze uncertain payload and reference for retry; block double-submit; explicit terminal/new-intent flow |
| TransactionHistory                              | Server response, filter/page callbacks, loading/error                                     | Desktop semantic table, mobile cards, all details preserved, reset page on filter, ignore stale reads                              |

API modules parse responses against shared contracts. Feature hooks own requests and cancellation; primitives and layout never fetch domain data. Money is never calculated as a JavaScript number. Browser session storage may retain an uncertain transaction intent for safe retry; it never stores database credentials or authoritative balances. A known account name comes only from account creation navigation state, otherwise the header uses Account and UUID.

Meaningful component behavior is verified independently before pages are assembled. Final checks include keyboard navigation, dialog focus, reduced motion, live API flows in an isolated database, automated accessibility checks, and 320/375/768/1024/1440px layout checks.

## Implementation and verification

The component-first gates were completed in order: primitive tests, independent navigation tests, landing/domain component tests, then page assembly and browser QA. Pages only compose the router, shared shell, sections and account workspace. `styles/layout.css` owns the 640px content and 1024px navigation breakpoints; the drawer reads the corresponding CSS token for its desktop reset.

`pnpm --filter @ledger/web test` runs 37 component/hook/page tests. They cover shared validation, stale-read cancellation, filter/page state, exact money, duplicate/uncertain writes, retained references across remount, delayed responses after navigation, and route recovery. A late response clears only its own persisted reference so it cannot erase a newer unresolved intent.

`pnpm test:e2e` runs 13 Chrome/Chromium tests against the real Express API and a disposable PostgreSQL 17 cluster. They cover the landing page and long account/history content at 320/375/768/1024/1440px, both drawer Tab directions, Escape/backdrop/resize/focus restoration, skip link and CTA focus, creation/UUID lookup, credit/debit/rejection flows, copy ID, filtering/pagination, and a response lost after commit followed by an identical-reference retry. Axe checks landing/account screens and the open drawer at representative mobile/desktop widths; these checks are not a complete accessibility certification.

The browser fixture never loads `apps/api/.env`. Explicit global teardown waits for its database to stop and remove its temporary directory before Playwright terminates the server group. See README for browser installation, ports, and startup commands. The configured Supabase database is not mutated by tests.
